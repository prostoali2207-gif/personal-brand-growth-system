## Objective and communication job

One authentic business problem for a non-technical owner: a customer request goes quiet and nobody notices. One takeaway: a simple status board makes a stuck request visible and gives it a next step. Service module shown: CRM only (request tracking, statuses, next action). It does not imply a website, automation or any other module.

## Concept alternatives (different mechanisms, not different styles)

| | A. Request journey | B. Same data, two containers | C. The forgotten request |
|---|---|---|---|
| Mechanism | one request moves through statuses on one panel | messy messenger/spreadsheet wipes into one board | an overdue row signals itself, someone acts, it resolves |
| Viewer question | "что будет с заявкой?" | "чем это лучше моего чата?" | "а у меня что-то зависло?" |
| Proof | status flips | contrast | alert plus status flips |
| Production | one panel | two UIs and a transition | one panel plus an alert state |
| Reference basis | R2 state-change badge | none inspected | R2 badge plus R1 pointer-led proof |
| Risk | happy path, low tension | needs a convincing mess; easy to look fake | alert color must stay readable in mute |

Selected: C. Reasons: the owner's pain is specific and immediate (a lost or forgotten request), the proof is a visible change on one cropped panel (the one mechanism supported by inspected references), production is one panel, and it can stay within the CRM module only. B is rejected for production cost and fake-looking risk; A is kept as the fallback if C reads as scary instead of useful in review.

## Storyboard (C), 16 s, 1080x1920, no music

Panel: generic request board, columns Client / Request / Status / Next step, five rows, placeholder names "Клиент А" to "Клиент Д", request types "Расчёт", "Консультация", "Повторный заказ" and similar. Cropped so that each critical word is large at phone size. Small tag "Демо-данные" stays in the frame the whole time.

| sec | viewer question | screen | text on screen | motion and why | readability / mute check |
|---|---|---|---|---|---|
| 0.0-2.0 | что это? | board visible from frame one, row 4 amber with "3 дня без ответа" | plate in top fifth: "Заявка зависла. Вы заметите?" | none at first frame; from 1.0 s row 4 pulses once so the eye lands on it | question readable without sound; amber row also has a text label, not color alone |
| 2.0-5.0 | какая именно? | other rows dim, ring around row 4 | plate: "Вот эта. Три дня тишины." | dimming isolates the proof (hierarchy) | text plus ring; no color-only meaning |
| 5.0-8.0 | что делать? | pointer enters, opens status list on row 4, picks "В работе"; panel scales up around the row | plate: "Берёте в работу" | pointer leads the eye; scale-in keeps row text legible | pointer path matches the text beat |
| 8.0-11.0 | и что дальше? | status badge on row 4 springs in "В работе"; next-step cell fills "Позвонить завтра 10:00" | plate: "Назначили шаг и срок" | spring-in badge marks the state change (reference R2) | badge text readable, cell text large enough |
| 11.0-14.0 | чем закончилось? | row turns green, badge "Закрыта"; counter at top "Зависших: 0" | plate: "Закрыта, а не забыта" | second state flip, same motion grammar as the first, so the viewer reads it instantly | counter and badge both text-bearing |
| 14.0-16.0 | кто это показал? | board dims, handle appears, row 4 returns to its amber start state for a seamless loop | handle `@nosignoutside` at about 70% of the height, below it "Демо-данные" | loop back to frame one; no ask | bottom 20% empty; handle readable on a phone |

Rhythm without music: one text change every 2 to 3 seconds, state flips at 8.0 and 11.0 s. The no-music rhythm is untested, to be judged in review.
