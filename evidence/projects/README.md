# Project evidence

One evidence packet per real project or coherent workstream. Evidence packets support source-of-truth records and brand claims; they are not promotional case studies by default.

Recommended filename: `<project-id>.md`.

## Minimum packet

- `project_id`
- `project_name`
- `repository_or_system_refs`
- `user_role`: only what evidence supports
- `time_scope`
- `problem_or_goal`: evidence-backed description
- `artifacts`: PRs, commits, issues, deployments, screenshots, recordings, product outputs, logs, etc.
- `observable_work`
- `observable_outcomes`
- `limitations / unknowns`
- `claim_candidates`: optional; each must still pass the brand-claim ledger
- `last_verified_at`

Separate direct evidence from interpretation. Do not infer clients, revenue, impact, ownership, authorship, technology use, or outcomes beyond what the cited artifacts support.
